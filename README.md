## A100：PCIe 和 SXM 差在哪，MIG 能切出什么

A100 是搜索量最大的一个型号，也是选型时最容易只看价格就下单的一个。它有两个形态，规格上的差别直接对应两种用法。

| 项目 | A100 80GB PCIe | A100 80GB SXM |
| --- | --- | --- |
| 显存 | 80GB HBM2e | 80GB HBM2e |
| 显存带宽 | 1,935 GB/s | 2,039 GB/s |
| 最大 TDP | 300W | 400W |
| 互联 | NVLink 600 GB/s；PCIe Gen4 64 GB/s | NVLink 600 GB/s；PCIe Gen4 64 GB/s |
| 形态 | 双槽风冷或单槽液冷 | SXM |
| MIG | 最多 7 个 10GB 实例 | 最多 7 个 10GB 实例 |

两种形态的计算精度指标完全一致：FP64 9.7 TFLOPS、FP32 19.5 TFLOPS、TF32 156 TFLOPS（稀疏 312）、BF16 与 FP16 Tensor Core 各 312 TFLOPS（稀疏 624）、INT8 312 TFLOPS（稀疏 624）。

SXM 的带宽高 104 GB/s，TDP 也高 100W。官方文档的说法是 SXM 形态“供电与散热更好，性能更高”，PCIe 形态“兼容多数服务器配置”。单卡跑推理，这点带宽差不明显；多卡做 NVLink 互联的训练任务，SXM 才是对的选择。

**MIG 是 A100 上一个被低估的功能。** 一张 A100 可以切成最多 7 个 10GB 实例，每个实例有独立的内存和计算资源，互不干扰。你要同时服务三四个小模型、或者给几个团队各分一块算力，就不用一人买一张整卡。Vultr 支持 A100 的 MIG，官方把这套用法明确指向多租户环境和“同时服务多个模型”的场景。

官方页面还引用 NVIDIA 的说法称 A100“最高可达上一代 GPU 的 20 倍性能”，这句没有给测试条件，按宣传口径看就行，别当成你的实际加速比。

## A40 的 $0.075 和 $1.712，是两个不同的东西

这是前排文章里最常被写错的一处。

Vultr 的 A40 产品页写着“Starting at $0.075 / hour”，同一页接着解释：Vultr 把物理 A40 切分成若干独立的虚拟 GPU，每块有自己的显存和算力。所以 **$0.075 买到的是一个最小 vGPU 切片，不是一张整卡**。整卡的起价是 $1.712/GPU/小时。

两个数字差 20 多倍，用途也不一样：

- 按切片买：适合虚拟桌面、云工作站、轻量图形任务，一个人用一小块就够，成本压得很低
- 按整卡买：48GB GDDR6 显存全给你，带宽 696 GB/s，NVLink 双向 112.5 GB/s，跑 Blender、Maya、Cinema 4D 的渲染，或者做光线追踪、虚拟制片、CAD

A40 的硬件底子是 Ampere 架构 CUDA 核心、第二代 RT Core、第三代 Tensor Core，支持 NVIDIA RTX Virtual Workstation、Virtual Compute Server、AI Enterprise 等 vGPU 软件授权，编码解码是 1 个 NVENC 加 2 个 NVDEC（含 AV1 解码）。

官方 FAQ 里把 A40 和 A100 的分工说得很直接：A100 强在训练，A40 在规模化推理上更具成本效益，尤其是在需要虚拟化的云环境里。你要训练模型，别在 A40 上省这个钱；你要部署推理或者做渲染农场，A100 是浪费。

## 按场景选卡

### 训练和微调大模型

从 A100 80GB 起步。80GB 显存能装下 7B 到 13B 量级模型的全参数微调，或者更大模型的 LoRA。模型再大、或者要多机多卡，往上就是 HGX H100（$2.300）、GH200（$1.990）、HGX B200（$2.890）。

B200 是 Blackwell 架构，每 GPU 最高 192GB HBM3e，支持 FP8 和 FP4，NVLink 做多卡扩展。MI355X 是 CDNA 4 架构，每 GPU 288GB HBM3e，同样支持 FP8/FP4。这两个型号解决的是同一类问题：单卡 80GB 装不下的模型。显存需求超过 80GB，A100 再便宜也帮不上你。

### 推理部署

看你的模型多大、并发多少。单模型、中等并发，A100 一张卡配 MIG 切成几个实例，性价比比堆几张卡高。多模型并行、每个模型都要独立显存，MIG 更合适。轻量模型、只要跑起来能用，L40S（$0.848）或 A16（$0.471）就够，官方把 L40S 定位在“兼顾性能与成本”这一档。

### 图形渲染与虚拟工作站

A40 整卡或 L40S。A40 的 48GB GDDR6 带 ECC，对渲染这类吃显存的任务很实在；L40S 把图形、AI 推理和视频处理放在一张卡上，官方列的场景是 3D 可视化、虚拟环境和视频处理。只做虚拟桌面、不跑重负载，A16 是最省的选择，官方就是拿它做虚拟桌面和虚拟工作站的。

### AMD 路线

MI300X（$1.850）、MI325X（$2.000）、MI355X（$2.290）走 ROCm 软件栈，不是 CUDA。选之前先确认你的框架和算子在这套栈上跑得通，官方提供了 AMD Inference Microservice 配合 AMD AI Workbench 的部署教程，说明推理这条路是官方主推的方向。CUDA 生态里那些依赖特定算子的项目，迁移成本要自己评估。

## 计费方式与真实成本

所有 GPU 价格都以“/hour”标注，按小时计费。这里有三件事容易算错。

**第一，$0.075 那个数字不能拿来估月账单。** 它是 A40 最小 vGPU 切片的单价，你按这个价格买不到整卡。要估整卡成本，用 $1.712。

**第二，官网没有公布月封顶价或包月折扣。** 拿单价乘 730 小时只是纯算术推演，不是官方报价。按这个算法，A100 PCIe 连续跑满一个月约 $941.70（$1.290 × 730），A16 约 $343.83（$0.471 × 730），A40 整卡约 $1,249.76（$1.712 × 730）。这三个数只能当量级参考，实际账单看控制台。

**第三，长期挂着和短时高峰的成本结构完全不同。** 按小时计费对训练任务友好，跑几小时停掉就只付几小时；对一个要 7×24 常驻的推理服务，账单会按上面那组数字往上走。如果你的负载是常驻型，先按 730 小时估一遍，再决定是留在云上还是换方案。

## 哪些情况不适合选 Vultr 的 GPU

**单卡 80GB 装不下你的模型。** 这不是 Vultr 的问题，是 A100 的问题。你要跑 70B 全参数微调或者更大，直接看 B200（192GB HBM3e/GPU）或 MI355X（288GB HBM3e/GPU），别在 A100 上反复折腾量化。

**你只需要跑一个小模型做演示。** 一张 A100 一小时 $1.29，一个月近千美元。这种需求用 A16 或 L40S，甚至用 Serverless Inference 按调用付费，成本差一个数量级。

**你要的是固定月费、账单可预测。** 官网目前只标小时价，没有公布月封顶。跑常驻服务的话，账单会随运行时长线性走，做预算时按小时价乘实际运行时长算，别按“一个月多少钱”的直觉估。

**你需要明确的退款或试用条款。** 公开资料里没有 Vultr GPU 实例的退款政策、免费试用期和 SLA 条款，下单前自己在控制台的计费页面或支持工单里确认清楚，尤其是打算长期投入的情况。

**你依赖 CUDA 特定生态。** AMD 那三张卡走 ROCm，性能参数很好看，但迁移成本是实打实的，先把关键算子跑通再决定。

## 常见问题

**A100 和 A40 怎么选？**

看你是训练还是推理/渲染。训练、微调、HPC、科学计算选 A100；推理部署、3D 渲染、虚拟工作站、CAD 选 A40。官方自己就是这么分的：A100 强在训练，A40 在规模化推理上更具成本效益。价格上 A40 整卡 $1.712 比 A100 的 $1.290 还贵，别以为数字大就是更强的训练卡。

**MIG 是什么，什么时候值得用？**

Multi-Instance GPU，把一张物理 A100 切成多个隔离的实例，最多 7 个 10GB 的。每个实例有独立显存和算力，互不干扰。你要同时服务多个模型、或者给多个团队/租户分算力，用 MIG 比买多张整卡省得多。单任务吃满整卡的时候，切了反而拖慢。

**按小时还是按月？**

目前只看到按小时计价的标注，没有月付套餐或月封顶价。用多少小时付多少小时的钱，短时任务很划算，常驻服务要自己乘一下。

**A100 PCIe 和 SXM 到底选哪个？**

单卡推理、对互联要求不高，PCIe 够用，兼容性也更好。多卡 NVLink 训练、追求带宽和散热，选 SXM。差别在 1,935 vs 2,039 GB/s 的带宽和 300W vs 400W 的功耗上。

**想跑 ComfyUI 或 Stable Diffusion，选哪张？**

官方有 ComfyUI 的部署教程，说明这条路是支持的。A100 80GB 跑得开，但对个人用途来说过剩；L40S（$0.848）或 A40 整卡更匹配图形生成这类负载，显存 48GB 也够大部分工作流。

**要多机多卡怎么办？**

用 Vultr Clusters，按需开通，控制台或 API 配置，Slurm 或 Kubernetes 调度，不需要提前申请或预留。
